# M4/M5 实现状态

## 状态

M4/M5 已完成可用的离线/快照闭环，真实管理员 ETL 已验证：

- `wperf stat`：进程时间、cycles、page faults、I/O 计数。
- `wperf top`：按 interval 捕获 ETL 并刷新 CPU 热点，属于 snapshot top，不是连续 ring-buffer top。
- `wperf script`：导出样本字段。
- `wperf trace`：离线输出 scheduler、syscall、pagefault、I/O 事件。
- `wperf sched`：按进程汇总 CSwitch/ReadyThread 计数。
- `record --profile cpu-sched|syscall|vm|io|kernel|all`。

## M4 已完成

- `stat -- command`、`stat -p PID`。
- `stat --per-thread` 基础线程时间/cycles。
- `stat` 输出：
  - elapsed
  - user
  - sys
  - cycles
  - pagefault
  - IO read/write
- `script -i FILE [--fields ...] [--limit N] [--csv]`。
- `top --interval MS --iterations N`：
  - 当前为 snapshot 实现，每次启动一次短 ETL，然后刷新 report。
  - 后续 issue 会替换为 real-time ETW consumer + bounded ring。

## M5 已完成

- `record --profile` 支持：
  - `cpu`
  - `cpu-sched` / `sched`
  - `syscall`
  - `vm`
  - `io`
  - `kernel`
  - `all`
- `trace -i FILE -e sched|syscall|pagefault|io`。
- `sched -i FILE` 汇总 CSwitch/ReadyThread。
- `trace --json`。
- `trace --max`。
- 事件模型：
  - ContextSwitch
  - ReadyThread
  - SyscallEnter/Exit
  - PageFault
  - DiskIo
  - FileIo
- 页错误和 I/O 事件按 ETW provider/class 解码。

## 真实验证

- `cpu-sched` ETL 产生 CSwitch/ReadyThread，`trace` 与 `sched` 可输出。
- `vm` ETL 产生 PageFault，`trace -e pagefault` 可输出。
- `syscall` ETL 产生 SyscallEnter/Exit，`trace -e syscall` 可输出 syscall 地址。
- `io` ETL 产生 FileIo，`trace -e io` 可输出。
- `top --iterations 1` 在管理员环境返回成功。
- `stat -- command` 在本机普通权限返回成功。

## 当前限制

- `top` 还是 snapshot capture，不是连续实时 ETW consumer。
- `trace` 当前为离线 ETL 模式，尚未做 live stdout。
- CSwitch/ReadyThread 的 PID 依赖 Thread rundown；部分系统线程会显示为 unknown。
- Syscall 事件通常没有进程 PID/TID，当前输出 syscall 地址；不会伪造 Linux 参数级语义。
- I/O 当前是事件级基础输出，尚未完成 init/complete 延迟关联。
- 以上限制已在路线图中保留，不与“已支持”混淆。
