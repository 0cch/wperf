# M0 可行性验证

M0 的目标不是实现完整 profiler，而是确认 Windows/ETW 能力边界和后续技术路线。

## 可执行验证

```powershell
pwsh -File .\scripts\m0_probe.ps1
```

管理员终端中会额外执行 xperf CPU 基准：

- `PROC_THREAD+LOADER+PROFILE`
- `-stackwalk Profile`
- 1 ms 采样
- 4 线程 CPU 负载
- 生成 `m0-cpu.etl` 和 `xperf-profile.txt`

## 产物

默认写入 `artifacts/m0/`：

```text
environment.json
wperf-version.txt
wperf-list.txt
wperf-doctor.txt
xperf-help-start.txt
summary.json
m0-cpu.etl
xperf-profile.txt
cpu-burn.txt
```

管理员且 xperf 可用时才会生成 ETL 和 profile 报告。

## M0 验收项

- `wperf list` 能列出 Timer 和平台 PMC profile source。
- `wperf doctor` 能识别管理员状态、最大 PMC counter、活动 ETW session。
- 管理员环境能用 xperf 生成 1 ms CPU sample + stack ETL。
- 能通过 `xperf -a profile -detail` 输出热点报告。
- 记录 LBR 探测状态。LBR 最终能力仍需在真实采集 session 上按硬件验证。

## 当前设计结论

- Windows 使用 ETW SystemTraceProvider 是可行路线。
- CPU sampling 和 stackwalk 可以作为 M2 的主路径。
- PMC source 数量可以通过 `TraceQueryInformation(TraceMaxPmcCounterQuery)` 获取。
- `TraceMaxLoggersQuery` 在部分非管理员/系统版本上不可用，需要降级显示。
- xperf 继续作为 M0/M2 的 golden trace 工具，不作为最终运行时依赖。
