# M6/M7 实现状态

## M6：PMC、LBR 和硬件能力

### 已实现

- `wperf list` 展示 ETW profile source：
  - Timer
  - TotalCycles
  - InstructionRetired
  - CacheMisses
  - BranchMispredictions
  - 等
- `record --profile pmu --pmc-source ID`。
- `stat --pmu -e TotalCycles -- command`。
- PMU capture 使用 ETW：
  - `TraceProfileSourceConfigInfo`
  - `TraceSampledProfileIntervalInfo`
  - system logger sampled profile
- PMU 停止后恢复 Timer source 配置。
- PMC sample/event extended counters 与 `pmc_counter_events` 质量字段。
- `stat --pmu` 输出 sample-derived 语义，不冒充精确 counter total。
- LBR 配置入口使用 `TraceConfigureLastBranchRecord`。
- 不支持的 LBR 平台会明确失败，不伪造结果。
- LBR payload 已实现 32/64-bit from/to 解码，最多 128 branch。

### 真实机器验证

当前 AMD Ryzen 7 8700G 环境：

- ETW PMC source 可用。
- `TotalCycles` source id：19。
- `stat --pmu -e TotalCycles` 成功。
- PMU profile 验证：
  - samples：4389
  - `wperf_cpu_burn.exe!Burn`：45.89%
- LBR：
  - `record --lbr` 返回 exit 4。
  - 当前平台/系统组合未验证 LBR 可用，因此标记为 unsupported/skipped。
- context register 已提供 `record --context-registers`，能力不支持时明确降级；寄存器 payload 解码等待可验证 schema。

### 重要说明

- ETW PMC 不是 Linux `perf_event_open` 的精确组计数语义。
- `stat --pmu` 当前输出是 **PMU profile sample 摘要**，不是精确 instruction/cycle total。
- PMU source 配置是系统级配置，停止时恢复 Timer。
- LBR 深度有限，不能代替 Intel PT。

## M7：高级分析和发布工程

### 已实现

- `annotate -i FILE`：
  - 采样地址热度
  - module/symbol/RVA
  - `--pid`、`--limit`
- `diff -1 FILE -2 FILE`：
  - 按 module/symbol 比较样本数变化
- `archive -i FILE -o DIR [-p PID]`：
  - 从 trace 使用的模块集合中复制存在的 PE/PDB
  - 生成 manifest
- `buildid-list -i FILE`。
- CSV/JSON/folded/calltree 输出。
- Windows CI 覆盖 M0-M7 的非提权 smoke。
- 发布脚本和单 EXE 构建。

### 当前限制

- `annotate` 已输出 source/line 和结构化数据；反汇编等待库选型。
- `archive` 输出 PE/PDB identity、SHA256、体积状态和 JSON/CSV/TXT manifest；系统模块可用性仍取决于本机路径。
- `diff` 支持 weighted、calltree、PID/DSO filter 和 CSV/JSON。
- 独立 `.symcache` 格式尚未实现，当前依赖 DbgHelp/symsrv 缓存。
- 真实 LBR payload 解码和历史对比需要支持该能力的 Intel 平台验证。
